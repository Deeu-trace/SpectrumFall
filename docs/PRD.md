# 音频处理与节奏游戏系统 — PRD

## 1. 产品目标

构建一款基于 Qt 6 的桌面应用，集音频解码播放、手写 FFT 频谱分析、多种实时可视化、节拍检测与节奏游戏于一体。核心体验：用户加载音频文件后，可在 4 种可视化模式间自由切换欣赏音乐频谱，也可进入节奏游戏模式——系统自动基于节拍检测生成 4 键下落式谱面，玩家以 D/F/J/K 按键击打获得判定与连击反馈。所有 FFT 与节拍检测算法均手写实现，不依赖第三方库。

## 2. 用户故事

1. **音乐可视化爱好者**：作为一名音乐爱好者，我希望加载本地音频文件后能实时看到频谱柱状图、圆形频谱环、波形示波器和瀑布图四种可视化效果，以便直观感受音乐的频率变化。
2. **节奏游戏玩家**：作为一名节奏游戏玩家，我希望系统能自动分析音频的节拍并生成下落式谱面，让我用 D/F/J/K 四个按键击打音符，获得 Perfect/Good/Miss 判定和连击统计，体验与音乐节奏同步的游戏乐趣。
3. **音频分析者**：作为一名对音频技术感兴趣的用户，我希望调整 FFT 窗口大小（512/1024/2048）并观察实时频域分解结果，以便学习理解频谱分析原理。
4. **音频播放用户**：作为一名普通用户，我希望在可视化或游戏过程中随时暂停、跳转、调节音量和播放倍速，以便灵活控制播放体验。

## 5. 待确认问题

1. **音频后端选择**：使用 QMediaPlayer 还是 miniaudio？QMediaPlayer 与 Qt Multimedia 集成更好但延迟较高；miniaudio 延迟更低但需自行管理音频回调与数据流。建议优先尝试 QMediaPlayer，若实时性不足再切换 miniaudio。
2. **FFT 数据获取路径**：若用 QMediaPlayer，需通过 `QAudioBuffer` 或 `QAudioDecoder` 提取 PCM 数据送入 FFT；若用 miniaudio 可直接在回调中取数据。两者架构差异较大，需在架构阶段确认。
3. **节拍检测精度要求**：课题未明确 BPM 估计误差范围，建议目标为 ±5 BPM 以内；节拍位置标注精度建议 ±50ms。是否满足课题评分标准需确认。
4. **谱面生成策略**：自动生成的谱面密度如何控制？建议根据 BPM 和能量分布自适应——低能量段稀疏、高能量段密集，并提供简单的密度档位（Easy/Normal/Hard）。
5. **60Hz 刞新下的 FFT 性能**：窗口大小 2048 时，每帧 FFT 计算量约 2048×log₂(2048) ≈ 22528 次复数乘加。需验证在 MSVC 2022 64-bit Release 构建下单帧 FFT 是否稳定在 16ms 以内。若超标可考虑：降采样、仅在可视化模式下运行 FFT、或降低可视化刷新率。
